# entail 외부 GPU 세션 실행 지시

아래 본문과 의미 보존 설계안, 외부 GPU 시험 규약을 GPU 사용이 가능한 세션에 함께 전달한다. 세 문서는 구현·평가 지시이며 아직 GPU 시험을 완료했다는 뜻이 아니다.

## 전달할 작업

entail의 저수준 의미 보존 방어를 블록 FP8 행렬곱 경계 하나에서 구현하고 실제 GPU로 평가해 주세요. 기준은 entail 2.1.4 d0769c6, 연구 자료 1c24387입니다. 제공한 설계안과 시험 규약을 먼저 읽고, 현재 로컬 변경과 GPU·엔진 환경을 확인한 뒤 지원 범위를 동결하세요. 다른 기준 커밋을 사용하면 그 차이를 기록하세요.

첫 목표는 생산자가 올바르게 만든 FP8 활성값·가중치·스케일의 의미를 소비 지점까지 전달하고, 보호 대상의 다음 연산이 미검증 결과를 받을 수 없게 만드는 것입니다. 일부 행 또는 워밍업의 pass를 전체 연산의 보증으로 사용하지 마세요.

기존 off/load/debug 동작은 비교 기준으로 유지하고 별도의 필수 보증 프로파일을 구현하세요. 그 API는 제안·미구현 상태에서 출발하므로 실제 구현된 이름과 지원 범위를 문서화하세요. 새 프로파일은 선언·hook 누락, unsupported 입력, 검사 예외·예산 초과에서 전달 허가를 발급하지 않아야 합니다. blocked와 repaired를 별도로 기록하세요.

의미 규칙은 핵심에 두고 어댑터에는 생산자·소비자를 읽는 연결과 복구 핸들을 두세요. 소비 지점의 shape에서 의미를 추측한 태그만으로 producer 보존을 주장하지 마세요. 실제 quantizer나 모델 형식 선언과 적재·패킹 경로에 출처를 연결하세요. 값·스케일·storage의 관계와 epoch가 바뀌면 기존 허가를 무효화하세요.

지원 eager 호출은 실제 출력 전체를 신뢰하는 참조와 비교한 뒤 전달하거나, 신뢰하는 참조로 실제 입력 전체를 계산하세요. 참조의 입력 해석과 지원 범위도 확인하세요. 시험용 판정 oracle은 entail과 엔진의 참조 함수를 복사하거나 호출하지 말고 같은 FP8 값·스케일 식을 독립적으로 구현하세요. 정상 calibration으로 허용치를 동결한 뒤 holdout에서 문턱을 바꾸지 마세요.

graph/compile 지원은 별도로 입증하세요. 워밍업 뒤 새 배치·stride·scale owner·epoch, 첫 64행 밖의 결함, 정상 캡처 뒤 replay에서 활성화되는 결함을 시험하세요. 지원할 수 없는 graph 경로는 보증 프로파일에서 거부하거나 eager 참조로 전환하고 그 사실을 공개하세요. Python hook이 replay마다 다시 실행된다고 가정하지 마세요.

작은 함수 시험의 정상 8개, 소비 과정 결함 12개, admission·미지원 4개부터 수행하세요. 현재 load와 새 보증 프로파일을 따로 평가하세요. off에서 실제 오차를 만드는 변이만 유효 결함으로 세고, 다음 연산의 전체 반환값 관찰로 출력 이전 개입을 판정하세요. 모든 정상 사례를 거부해서 유출 0만 만드는 구현은 실패입니다.

함수 gate 뒤 실제 FP8 모델 하나에서 producer와 consumer의 도달을 확인하세요. RNG, cache, 입력·출력 버퍼와 반복 호출의 비간섭을 검사하고 비용을 따로 측정하세요. 실제 엔진 경로에 닿지 않았으면 함수 성과만 보고하세요. 환경에 모델이 없으면 작은 함수 시험을 먼저 마치고 엔진 gate는 미검증으로 남기세요.

구현이 끝나면 holdout 생성과 평가를 코드·프로토콜 동결 뒤 분리하세요. 별도 평가자가 없으면 독립 seed·변이로 분리하고 눈가림이라고 부르지 마세요. 결과를 본 뒤 필요한 수리는 새 판으로 남기며 원래 실패를 덮지 마세요.

산출물은 검토 가능한 코드 patch, 실행 계획·계약·허가 기록, freeze manifest, GPU 환경과 설치물 hash, 실행 명령, 입력·전체 oracle·전체 출력, 전달 관찰, stdout·stderr·exit code, RNG·cache·buffer 상태, 시간 원표와 사례별 결과입니다. 최종 보고는 교정 전달, 명시적 차단, 오답 유출, 정상 실패, 미검증, 실행 오류를 분리하고 보존과 실용성 예산의 판정을 따로 내세요.

이 단계의 완료는 블록 FP8 경계의 고정된 환경과 지원 범위에 대한 것입니다. 모델 전체, 임의의 커널, 새 GPU 세대 전체에 대한 보증으로 확대하지 마세요. 다음 경계를 추가할 때 같은 구조와 독립 평가를 반복할 수 있는지 설명해 주세요.
