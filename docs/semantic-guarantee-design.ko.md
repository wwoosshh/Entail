# entail 의미 보존 보증 설계안

2026년 10월 1일. 기준은 entail 2.1.4의 d0769c6과 연구 저장소의 1c24387이다. 이 문서는 제안이며 아래 보증 프로파일과 허가 체계는 아직 구현되지 않았다. 외부 GPU 세션은 함께 제공하는 시험 규약에 따라 구현과 검증을 진행한다.

목표는 지원 범위의 연산에서 생산자가 만든 데이터의 의미가 소비 과정에서 바뀌는 일을 예방하고, 산술 결과도 확인한 뒤 다음 연산으로 전달하는 것이다. 모델 답변의 사실성이나 추론 스택 전체의 무오류를 보증하지 않는다. 범위를 표시하고, 확인하지 못한 실행에는 보증을 부여하지 않는 것이 기능의 일부다.

## 보증의 정의

보호 범위 S와 신뢰하는 구성요소를 먼저 명시한다. S 안에서 결과를 전달했다면 필수 의미 계약을 검사했고, 해당 실제 결과가 약속한 수치 허용 범위를 만족해야 한다. 그렇지 않으면 전달 전에 정상 경로로 다시 계산하거나 명시적으로 거부한다.

- 의미 계약 보증: 선언된 역할, 축, 스케일 대응, 버전과 소비자의 전제가 일치한다.
- 실제 결과의 수치 확인: 해당 호출의 전체 출력이 신뢰하는 참조와 사전 고정한 오차 범위 안에서 일치한다.
- 표본 점검: 워밍업이나 일부 행만 비교한 결과다. 이후 호출 전체의 보증으로 승격할 수 없다.

이 세 가지를 별도 증거로 기록한다. 작은 탐침에서 통과했다는 이유로 프로세스 전체나 LLM 전체를 보증하지 않는다. 실제 결과의 수치 확인도 참조 구현, 검사 코드, 런타임과 장치의 메모리 실행이 정상이라는 가정을 가진 조건부 보증이다. 임의의 하드웨어 손상이나 검사기와 참조가 공유하는 결함까지 배제하는 완전한 증명은 아니다.

## 현재 구현과의 차이

현재 기본 정책은 해결되지 않은 broken과 unknown을 보고하고 계속한다. 함수 참조 비교는 제한된 입력 조각을 검사하고, compile과 graph 경로에는 적용 제약이 있다. 기존 모드의 동작을 보증이라고 다시 이름 붙이면 안 된다.

제안은 기존 off, load, debug와 구분되는 필수 보증 프로파일이다. 정확한 API 이름은 구현 때 문서화한다. 현재 지원하지 않는 환경변수나 명령을 이미 사용할 수 있는 것처럼 안내하지 않는다. 향후 제품에서 단순히 켜는 행위를 보증과 연결하려면 기본 활성화가 이 강제 프로파일을 선택하고, 기존 보고 전용 실행은 별도 선택으로 드러나야 한다. 이번 시범에서는 기존 사용 흐름을 유지하면서 새 프로파일을 분리해 비교한다.

현재 기반은 [정책](https://github.com/wwoosshh/Entail/blob/d0769c6/entail/policies.py), [함수 참조 어댑터](https://github.com/wwoosshh/Entail/blob/d0769c6/entail/adapters/function_reference.py), [연산 정의](https://github.com/wwoosshh/Entail/blob/d0769c6/entail/definitions.py)다. 새 규칙은 핵심에 두고, 어댑터는 엔진의 생산 지점과 소비 지점을 읽고 복구 핸들을 제공한다. 이는 [기여 규칙](https://github.com/wwoosshh/Entail/blob/d0769c6/CONTRIBUTING.md)을 따른다.

## 실행 계획과 출력 허가

실행은 다음 순서를 따른다.

1. 보호 범위, 필수 생산자와 소비자, 계약 버전, 허용 입력과 엔진 환경을 가진 실행 계획을 만든다.
2. 실제로 필요한 hook과 경로가 설치됐는지 확인한다. 기록이 없는 경계를 통과로 세지 않는다.
3. 생산자가 값을 만들 때 의미 선언과 생명주기 정보를 함께 발급한다.
4. 소비자 dispatch 직전에 선언과 실제 입력, 소비자의 전제를 대조한다.
5. 불일치는 알려진 변환이나 참조 경로로 교정하고, 바뀐 값과 경로를 다시 확인한다.
6. 전체 실제 출력의 수치 조건을 확인한 뒤 그 호출에 한정된 전달 허가를 발급한다.
7. 허가가 없는 값은 보호 범위의 다음 연산에 전달하지 않는다.

필수 경계의 unknown, hook 누락, 검사 예외, 시간 또는 메모리 예산 초과, 지원 밖 옵션은 허가를 발급하지 않는 결과다. 보고 줄을 남긴 뒤 원래 커널 출력을 계속 전달하는 동작은 보증 프로파일에서 허용되지 않는다. 검사기의 장애를 사용자 코드의 오류와 구분해 기록하되, 정상 결과로 위장하지 않는다.

첫 시범의 전달 지점은 행렬곱 결과 텐서를 다음 연산에 넘기는 곳이다. 향후 서버 응답까지 범위를 넓힐 때는 스트리밍 조각도 해당 조각에 필요한 검사가 끝난 뒤 발행해야 한다. 이미 전송한 잘못된 토큰을 사후 로그로 되돌릴 수는 없다.

## 첫 보호 범위

첫 시범은 vLLM 0.30의 Triton dense 블록 FP8 행렬곱 하나로 한다. 함수 단위 GPU 시험부터 시작하고 실제 엔진의 같은 경로까지 연결한다. 보호 대상 모델 전체나 다른 FP8 backend의 보증으로 표시하지 않는다.

의미는 A가 활성값 M×K, B가 가중치 N×K, As가 토큰별 K 그룹 스케일, Bs가 N·K 블록별 스케일이라는 것이다. 블록 크기가 gn·gk이면 As의 논리 shape는 M×ceil(K/gk), Bs는 ceil(N/gn)×ceil(K/gk)다. 유효한 스케일을 적용한 활성값 a와 가중치 b를 사용해 a @ b.T를 계산하고 출력 자료형으로 변환한다. 이것은 현재 연산 정의에도 명시돼 있다.

생산자 증거는 실제 양자화·패킹 함수가 발급해야 한다. 소비 함수에 도착한 뒤 shape만 보고 뜻을 추정해서 표지를 붙이는 것은 생산자 의미 보존으로 인정하지 않는다. 이미 양자화된 모델의 경우 파일 형식의 선언을 읽고 적재·재배열에서 그 선언을 보존하며, 활성값의 스케일은 실제 활성값 양자화 지점에서 연결한다.

초기 지원 자료형, 블록 크기, 입력 크기, 양의 유한 스케일, 허용 stride, 출력 dtype는 외부 환경 조사 뒤 시험 전에 고정한다. UE8M0, 전문가 병렬, multi-GPU, 임의 alias와 추적하지 못하는 in-place 변경 등은 첫 프로파일에서 지원한다고 가정하지 않는다. 지원하지 않는 조건은 명시적으로 거부하며 성공 집계와 분리한다.

## 값에 붙일 의미와 생명주기

| 정보 | 요구 조건 |
|---|---|
| 역할과 축 | activation, weight, activation scale, weight scale 및 M·N·K의 대응 |
| 표현 | dtype, shape, stride, storage offset, quantization block과 scale 형식 |
| 관계 | 어느 값의 어느 축·블록에 해당 스케일을 적용하는지 |
| 출처 | 실제 producer, 모델 또는 가중치 revision, 계약 버전 |
| 생명주기 | 값과 storage의 소유자, mutation epoch, 관련 스케일의 epoch |
| 소비 조건 | 커널 설정, 선택 backend, 출력 dtype, precision 정책 |

실제 객체와 storage를 유지하는 관계로 표지를 관리한다. 재사용된 포인터나 Python id만으로 같은 값을 판정하지 않는다. view, reshape, transpose, 이동, 복사는 연산이 뜻을 어떻게 옮기는지에 따라 표지를 변환한다. in-place 변경이나 새 스케일은 관련 허가를 무효화한다.

mutation 추적이 완전하지 않으면 불변 복사본이나 소유권 제한으로 보증 범위를 좁힌다. inference mode의 tensor version counter만으로 모든 변경을 추적한다고 가정하지 않는다. PyTorch는 inference mode에서 view 추적과 version counter 갱신을 줄이거나 없앤다고 명시한다. [PyTorch inference mode](https://docs.pytorch.org/docs/2.14/generated/torch.autograd.grad_mode.inference_mode.html)

검사와 사용 사이에도 입력·스케일의 의미가 바뀌지 않아야 한다. 같은 불변 snapshot 또는 쓰기 소유권과 stream 순서 보장을 사용해 실제 커널과 참조가 같은 값을 읽게 한다. 필요한 GPU 작업의 완료를 확인한 뒤 전달하고, 허가받은 출력 버퍼가 재사용되거나 변경되면 기존 허가를 폐기한다. snapshot 일치와 소유권을 확인할 수 없는 alias·비동기 쓰기는 첫 프로파일에서 거부한다.

## 실제 결과의 확인

엄격한 시범에서는 매 보호 호출마다 다음 중 하나를 수행한다.

- 커널 출력을 별도 버퍼에 받고, 동일한 불변 입력의 전체 참조 결과와 비교한 뒤 전달한다.
- 신뢰하는 참조 구현으로 실제 입력 전체를 직접 계산하고 그 결과를 전달한다.

참조도 동일한 양자화 값을 사용한다. 원본 비양자화 모델과의 차이를 실행 결함으로 세지 않는다. 참조의 해석과 지원 범위를 별도 검증하고, 정상 calibration으로 수치 허용치를 먼저 고정한다. 일부 행만 비교하는 빠른 모드는 표본 점검으로 기록한다. 성능을 맞추기 위해 이 모드를 수치 보증이라고 부르지 않는다.

새 구현이 왜 모든 허용 입력에서 옳은지 별도 증명을 제공하는 경우에는 해당 증명과 실행 조건을 계획에 연결할 수 있다. 유한한 GPU 시험을 통과한 커널은 그런 증명으로 취급하지 않는다.

## 컴파일과 CUDA 그래프

graph나 compiled artifact의 재사용은 다음에 묶인다: 실행 계획과 계약 버전, 실제 구현 fingerprint, engine·compiler·GPU architecture, shape·stride·dtype·precision, 특수화된 옵션, buffer 관계와 epoch. 바뀐 조건에서는 새 검증과 재캡처, 참조 경로 또는 명시적 거부를 선택한다.

워밍업에서 안전 경로를 선택했다면 그 경로가 실제로 캡처되었는지 확인한다. 호스트 hook을 replay마다 다시 호출한다고 가정하지 않는다. PyTorch는 CPU 작업이 graph replay에서 생략되고, 같은 주소와 shape·layout이 재사용된다고 명시한다. [CUDA graph 제약](https://docs.pytorch.org/docs/2.14/notes/cuda.html#constraints)

첫 시범에서 graph 안의 전체 결과 검증과 전달 gate를 안전하게 구성할 수 없으면 보증 프로파일이 해당 캡처 경로를 거부하거나 eager 참조 경로로 전환한다. 이 경우 오류 유출 차단과 graph 지원 성공은 별도로 기록한다. eager에서만 검사하고 미검증 graph를 그대로 재생하는 동작은 실패다.

실제 graph 실행이 시작된 뒤에도 커널의 수치 결함은 드러날 수 있으므로, artifact 인증만으로 매 실제 결과의 확인을 생략하지 않는다. torch.compile의 기존 guard가 entail의 의미 계약까지 검사한다고 가정하지 않는다. [PyTorch guard 설명](https://docs.pytorch.org/devlogs/dynamo/2025-06-04-inside-torch-compile-guards/)

## 기록과 사용자에게 보여 줄 범위

각 호출 기록에는 plan·contract·environment fingerprint, producer와 consumer, value·epoch, 검사 범위, 허용치, 비교한 전체 원소 수, 교정 전후 경로, 재확인 결과, 전달 허가와 실제 전달 여부를 담는다. 텐서 원자료는 시험 산출물에 따로 저장한다.

결과는 교정해 전달, 정상 전달, 명시적 차단, 미검증, 실행 오류로 구분한다. blocked를 repaired에 합치지 않는다. 실제 출력 없이 모든 요청을 거부하는 구현도 안전하게 멈출 수는 있지만 정상 사용 가능성 시험에 실패한다.

표시는 블록 FP8 경계의 확인 결과라고 말한다. 필수 경계 전체가 보호된 실행 계획이 있을 때만 그 계획의 보증을 표시한다. 다른 연산이 미검증인 LLM 요청을 전체 의미 보존 완료로 표시하지 않는다.

## 구현 순서

1. 보호 범위와 신뢰 가정을 기계적으로 표현하고 admission 실패를 전달 gate에 연결한다.
2. 실제 producer와 consumer 사이의 스케일·배치·epoch 관계를 강제한다.
3. eager 호출에서 전체 결과 확인 또는 참조 계산과 전달 gate를 구현한다.
4. 새 shape·stride·스케일·가중치·환경에서 기존 허가를 재사용하지 못하게 한다.
5. graph·compile 경로를 별도로 지원하거나 명시적으로 거부한다.
6. 함께 제공하는 GPU 규약으로 정상 동작, 결함 주입, 원자료와 비용을 검증한다.

핵심 성패는 검사 규칙 개수보다 이 한 경계에서 미검증 결과를 전달할 수 없는지에 있다. 이 구조가 검증되면 KV, reduction, position 등 다른 경계를 같은 형식으로 연결한다. 해당 순서와 단계는 제안이며 현재 성능 결과로 제시하지 않는다.
